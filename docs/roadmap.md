## 2. ビンゴ／クイズ結果を KV で管理者へ送る

### いまの状態

| アプリ | 結果の置き場 | 管理者への共有 |
|--------|--------------|----------------|
| ビンゴ | 端末の localStorage 中心 | なし（画面を見るだけ） |
| クイズ | 端末ローカル／URL 設定 | なし |
| アンケート | すでに **KV** で同期 | Host 画面で確認可 |

ビンゴ・クイズは「個人プレイ／URL 配布」向きのため、**結果の集約がない**。次はここを足したい。

### ゴール

- ゲスト端末で出た **ビンゴ達成** や **クイズ得点** を、サーバー側（KV）に残す  
- **管理者（幹事・司会）** が後から一覧・詳細を見られる（または通知を受けられる）

### 想定ユースケース

| 誰 | 何をしたいか |
|----|----------------|
| ゲスト | 今までどおり遊ぶ（操作を増やしすぎない） |
| 管理者 | 誰がビンゴしたか、クイズの点数分布を確認する |
| 管理者 | 二次会後に結果を振り返る（TTL 内） |

### 方針案（検討用）

```text
ゲスト端末
  → POST /api/...（結果送信）
  → KV に保存（ルーム or イベント単位の key）
  → 管理者画面 or Host 用 URL で一覧表示
```

| 項目 | 案 |
|------|----|
| 識別 | アンケート同様の **ルームコード**、またはイベント用の管理キー |
| KV キー例 | `bingo:{room}` / `quiz:{room}` に結果配列を保存 |
| TTL | アンケート同様 24h 程度（二次会用途） |
| プライバシー | 氏名は任意・端末内だけ、など方針を先に決める |
| 管理者の見方 | 専用の簡易管理ページ、または既存 Host 画面にタブ追加 |
| 「送る」の意味 | (A) KV に溜めて管理画面で見る / (B) メールや Webhook 通知。まずは **(A) を推奨** |

※ 「管理者へ送る」は、最初からメール必須にせず、**KV 保存 + 管理画面表示** から始めると実装が軽い。通知はその次。

### ビンゴで送りたいデータの例

| フィールド | 例 |
|------------|----|
| 達成時刻 | すでに表示している日時 |
| ビンゴ数 | 何ライン達成か |
| ニックネーム | 任意（入力があれば） |
| ルーム／イベント ID | 管理者が発行 |

### クイズで送りたいデータの例

| フィールド | 例 |
|------------|----|
| 得点 / 正答数 | 例: 4/5 |
| 所要時間 | 任意 |
| ニックネーム | 任意 |
| ルーム／イベント ID | 管理者が発行 |

### 完了の目安

- [ ] ゲスト操作から結果が KV に残る  
- [ ] 管理者が URL または画面で結果一覧を見られる  
- [ ] 本番とプレビューで KV を分けられる（既存の `id` / `preview_id` 方針に合わせる）  
- [ ] 要件定義・設計書（`docs/requirements.md` / `docs/design.md`）を更新する  

### 注意（先に決めること）

- 個人情報（本名など）をどこまで扱うか  
- 改ざん（クライアントから偽スコア送信）をどこまで防ぐか（署名・Host シークレットなど）  
- アンケート用 `POLL_KV` に同居するか、別名スペースにするか
