## 0. この文書の読み方

**シナリオテスト**とは、「ユーザーが画面上でこういう順番で操作したとき、こうなるはず」という**物語単位**の確認です。  
「部品が正しいか」は単体テスト（L1）、「通信が生きているか」はスモーク（L2）の領域です。この文書は **L2b（E2E）** の合格条件の正本です。

| 似ている言葉 | ちがい |
|--------------|--------|
| 単体テスト（L1） | 部品（関数）だけを見る。画面は開かない |
| スモーク（L2） | 通信が通るかの短い確認。操作の物語はほぼ無い |
| **シナリオ／E2E（L2b）** | ブラウザで一連の操作をする。**この文書の主役** |
| 手動確認（L3） | 人がプレビューで触る。自動化しにくい・稀な経路向け |

自動実行は **ガーキン記法**（「前提・もし・ならば」）の `.feature` ファイルと、Playwright のステップ実装で行います。結果は **動画（webm）** で後から見られます。

| 読みたいこと | 読む場所 |
|--------------|----------|
| シナリオ一覧と合格条件 | この文書 §3 以降 |
| 用語（E2E・ガーキンなど） | [test-spec.md 用語集](./test-spec.md#1-用語集この文書で使う言葉) |
| 実行コマンド・動画・pre-push | [ops/testing.md](./ops/testing.md) |
| 要件の受け入れとの対応 | この文書 §1 · [requirements.md §7](./requirements.md) |

## 1. 目的

要件の受け入れ条件（抜粋）を、**再現可能なシナリオ**として定義し、可能なものは自動で毎回確認する。

| 受け入れ（要件 §7） | 対応シナリオ ID |
|---------------------|-----------------|
| 1. LP から3アプリに遷移できる | SC-LP-02 |
| 2. ビンゴで名前→達成→日時 | SC-BINGO-01 |
| 3. クイズを URL 共有し別端末で同じ問題 | SC-QUIZ-01 |
| 4. Host→ゲストURL→投票→結果表示 | SC-POLL-01 · SC-POLL-02 |
| 5. Host が押しても票が増えない | SC-POLL-03 |
| 6. デプロイ後の本番再現 | （手動 L3／本番。自動は非本番向け） |

## 2. 方針

| ID | 方針 |
|----|------|
| SC-P01 | シナリオは **利用者視点の言葉**で書き、実装の内部名に依存しすぎない |
| SC-P02 | 自動可能なものは **ガーキン + Playwright** で L2b として実行し、**動画を残す** |
| SC-P03 | テスト用ルームは **`T` 始まり**（アンケート）。本番イベントとぶつからないようにする |
| SC-P04 | 本番 URL・本番 KV はシナリオ自動実行の対象にしない |
| SC-P05 | 1 シナリオは **1つの利用者ゴール**に絞る（長くしすぎない） |
| SC-P06 | 自動と手動を表で明示する。手動はプレビュー手順とセットで実施 |

## 4. シナリオ詳細

各シナリオは次の形式です。

- **ゴール**: 利用者が達成したいこと  
- **前提 / 操作 / 期待**: 合格条件  
- **自動化**: 対応するガーキンとステップ  

---

### SC-LP-01 — ブランド名がヒーローに表示される

| 項目 | 内容 |
|------|------|
| ゴール | 紹介ページを開いた人が「ことほぎ」だと分かる |
| 前提 | アプリ（または E2E 用サーバー）が起動している |
| 操作 | LP（`/`）を開く |
| 期待 | 画面上に「ことほぎ」と表示される |
| 自動化 | ✅ `landing.feature` |

```gherkin
シナリオ: ブランド名がヒーローに表示される
  もし LPを開く
  ならば 画面に "ことほぎ" と表示される
```

### SC-LP-02 — Features から3アプリへ遷移できる

| 項目 | 内容 |
|------|------|
| ゴール | LP からビンゴ・クイズ・アンケートに進める |
| 前提 | LP を開いている |
| 操作 | Features 内の各アプリへのリンクを開く |
| 期待 | それぞれ該当アプリの画面タイトル／主要 UI が見える |

| リンク名（目安） | 遷移先 | 期待する目印 |

| 人間ビンゴ | `/app-tools/wedding-bingo/...` | 「Wedding Bingo」など |
| 新郎新婦クイズ | `/app-tools/wedding-quiz/...` | 「Wedding Quiz」など |
| リアルタイムアンケート | `/app-tools/wedding-poll/...` | 「Live Poll」または入室 UI |

| 期待 | 各アプリリンク内に「使い方」と幹事／司会向けの短い手順がある |

### SC-POLL-01 — Host が入室し Guest が投票できる

| 項目 | 内容 |
|------|------|
| ゴール | 司会がルームを作り、ゲストが投票できる |
| 前提 | アンケート開始画面。Host モードでは司会向け使い方が見える（Guest モードでは隠れる） |
| 操作 | Host が入室 → ゲスト URL を別ブラウザ相当で開く → 先頭の選択肢で投票 |
| 期待 | Host に質問編集ボタンがある。Guest に「投票済み」が表示される |
| 自動化 | ✅ `poll.feature` |
| ルーム | 実行ごとに `T***` を新規発行 |

---

### SC-POLL-02 — Guest 投票後、Host が結果を表示できる

| 項目 | 内容 |
|------|------|
| ゴール | 司会が結果を会場に見せられる |
| 前提 | SC-POLL-01 と同様に Guest が1票入れたあと |
| 操作 | Host が「結果を表示」を押す |
| 期待 | 結果エリアが見え、票数が反映されている（合計が1以上） |
| 自動化 | ✅ `poll.feature` |

---

### SC-POLL-03 — Host は選択肢を押せない（投票不可）

| 項目 | 内容 |
|------|------|
| ゴール | 司会が誤って票を入れられない |
| 前提 | Host としてセッション画面を表示している |
| 操作 | 選択肢が無効であることを確認し、強制クリックしても API 上の票が増えないことを確かめる |
| 期待 | 選択肢は disabled。ルームの票合計は 0 のまま |
| 自動化 | ✅ `poll.feature` |

---

### SC-POLL-04 — Host が質問を編集すると Guest にも反映される

| 項目 | 内容 |
|------|------|
| ゴール | 司会が質問文を変え、ゲスト画面にも届く（要件 P-10） |
| 前提 | Host としてセッションに入室し、ゲスト用 URL がある |
| 操作 | 「質問・選択肢を編集」で先頭の質問文を変更して保存 → Guest が URL を開く |
| 期待 | Host / Guest 双方の質問文に編集内容が表示される（票はリセットされる） |
| 自動化 | ✅ `poll.feature` |

---

### SC-BINGO-01 — 名前入力でビンゴ達成し日時が表示される

| 項目 | 内容 |
|------|------|
| ゴール | マスを埋めてビンゴになり、達成時刻が見える |
| 前提 | ビンゴ画面。幹事用編集画面に使い方の要点がある。中央 FREE は「主役の2人」で埋まっている |
| 操作 | 中央を含む1ラインが揃うよう、残りマスに名前を登録する（例: 中央行の左右） |
| 期待 | ビンゴ達成の表示が出る。達成日時（日付・時刻）が表示される |
| 自動化 | ✅ `bingo.feature` |

### SC-QUIZ-01 — 共有 URL を開くと同じ問題セットになる

| 項目 | 内容 |
|------|------|
| ゴール | 幹事が配った URL で、ゲストも同じ問題を解ける |
| 前提 | クイズ画面。幹事用編集画面に使い方の要点がある |
| 操作 | 問題を識別できる内容に編集し共有 URL を作る → 別コンテキストでその URL を開いてクイズ開始 |
| 期待 | 同じ問題文（または編集した目印）が表示される |
| 自動化 | ✅ `quiz.feature` |

### SC-TOOLS-01〜03 — 幹事・進行ツール群（機能が成立するか）

| 項目 | 内容 |
|------|------|
| ゴール | 追加ツール（TOOL-\*）が一覧から開け、主要操作が成立する |
| 前提 | 一覧ページ（`/app-tools/index.html`）または各ツールページを開ける |
| 自動化 | ✅ `tools.feature` |

| ID | シナリオ | 主な操作 | 期待 |
|----|----------|----------|------|
| SC-TOOLS-01 | 一覧から遷移 | 一覧を開く → 「ビンゴ数字抽選機」を開く | 一覧に主要ツールのリンクがあり、抽選機画面へ遷移する |
| SC-TOOLS-02 | 抽選機で抽選 | 抽選機を開く → 「抽選する」 | 使い方が表示され、数字が1つ出て抽選済み数が 1 になる |
| SC-TOOLS-03 | 割り勘計算 | 割り勘計算機を開く | 一人当たりの金額（¥）が大表示される |

代表ツールを自動化し、残りのツールは共通ロジック（UT-PARTY-\*）と目視（L3）で担保する。  
（旧 SC-TOOLS-04 / 05 は対象ツール廃止に伴い削除）

### SC-TOOLS-06〜10 — 幹事・進行ツール群（当日使えるか）

機能が動くことと、**マイクを持ったまま当日使えること**は別なので、操作性の約束（要件 T-07〜T-09）を独立したシナリオとして固定する。ツールごとに同じ作りを共有しているため（design §5.3b）、代表 1 ツールで守れていれば全体の回帰を検知できる。

| 項目 | 内容 |
|------|------|
| ゴール | 入力不足・押し間違い・結果の持ち帰りが、進行を止めずに扱える |
| 前提 | 各ツールページを開ける。localStorage は初期化した状態 |
| 自動化 | ✅ `tools.feature` |

| ID | シナリオ | 主な操作 | 期待 |
|----|----------|----------|------|
| SC-TOOLS-06 | 入力不足の伝え方 | ルーレットを開く → 候補を1件だけにする | 回すボタンが無効になり、件数（1件）が画面に出る。ダイアログは出ない |
| SC-TOOLS-07 | 結果の持ち帰り | 割り勘を開く → 「集金メモをコピー」 | 「集金メモをコピーしました」の通知が表示される |
| SC-TOOLS-08 | 一覧の絞り込み | 一覧を開く →「割り勘」で絞り込む | 割り勘計算機は残り、関係ないツール（抽選ルーレット）は隠れる |
| SC-TOOLS-09 | 加点の取り消し | 得点板を開く → 先頭チームに加点 → 「1つ元に戻す」 | 得点が 1 になった後、0 に戻る |
| SC-TOOLS-10 | 抽選の取り消し | 抽選機を開く → 「抽選する」→「1つ取り消す」 | 抽選済みが 1 → 0 に戻り、表示も数字でなくなる |
